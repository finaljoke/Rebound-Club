# 对打小样 · 对手平衡实验：追球与回位分开、重炮施压留机会、两种打法对比、提示分档

## Background and goal

对打小样（变更 `2026-10-23-rally-prototype`，已 complete）已经能打完整局，但审阅发现：读球机器人三局都是 5:0。在模拟中，面对打得准的玩家，对手每次失分时都没够到那颗球；面对随机挥拍的玩家，对手只能靠玩家失误得分。当时的检测只确认了「能否打完整局」，没有检查「普通回击」和「精准反制」的收益差别。

本轮不加新技能，只做**对手平衡实验**。目标是四句话（用户原话）：

> 普通球能来回，强攻会施压，读招能获益，调动能得分。

真正要回答的问题是：玩家能不能感受到「我看懂了这招，抓住机会赢下这一分」。机器人数据只能说明数值是否落在可以拿去试玩的范围，不能代替真人结论。

## Confirmed decisions

来源：用户 2026-10-23 对审阅报告的回复。

1. 已通过的小样变更保持 complete；这一轮单独做对手平衡实验，暂缓增加新技能。
2. 不直接把对手速度改回 4.2：追球和回位要**分开调**。对手能接住多数普通球；被调动到边路后，回位仍有破绽，让玩家通过连续落点创造机会。
3. 重炮要形成压力，同时留下机会：**出招前检查时间是否够蓄力**；普通回击可以保命，精准反制应更容易取得主动。
4. **比较两种打法**：在相同移动水平下，分别测试「只用普通回击」和「主动反制」，观察得分率、回合长度和反制后的优势。
5. **提示分两档**：教学档保留「现在反制！」；正常挑战主要靠引拍、声音和光效读招，再让真人比较两档的体验。
6. 机器人连续 5:0 是警讯，但不能直接推断真人会觉得太简单。

## Current state with evidence

（阅读 `sites/ball-guard/dist/rally-core.mjs`，小样文件尚未提交，基于 HEAD `69abec5` 工作区）

- **追球与回位**：`moveActors`：球由玩家击出后，对手经过 `reaction` 延迟，以 `RALLY.aiSpeed`（2.6）横向追向预测接触点；球由对手击出后，以 `aiSpeed*aiRecovery`（2.6×0.45≈1.17）回到 `x=0`、`z=8.9`。两者共用 `aiSpeed`。
- **对手出球**：`opponentStrike` 的落点固定为玩家当前位置的对侧 `x=±2.8`（只加 ±0.12 的小扰动），纵深 1.65；普通球飞行时间 `normalTime`（1.65），重炮为 `min(heavyTime,距离/heavyMinSpeed)`。对手的普通球不会失误。
- **重炮决策**：`decideOpponent` 在玩家来球越网时决定，条件是软球、预测第一落点 z<7.2，或 `(a.hits+1)%4===0`；**不检查剩余时间**。出手前一定会等满 `RALLY.tell`（0.5 秒），见 `tick` 中 `opponentStrike` 的条件。
- **玩家面对重炮**：`shotKind` 中，来球为 `heavy` 时，`|t|≤counterWindow(0.18)` 为反制，否则为软球；反制回球速度 ×1.1，对手额外延迟 `counterDelay`（0.15）。
- **提示**：`dist/rally.js` 第 63–64 行，击球区在反制时机加 `counter` 样式，文字提示显示「现在反制！」，没有分档。
- **检测**：`scripts/rally-qa.mjs` 用读球机器人打整局；`tests/rally-core.test.mjs` 中两项「真实回合可结束」测试的机器人总是在最佳时机出手。审阅模拟：打得准的机器人 200 分全胜；随机挥拍的机器人，对手拿到 70 分，全部来自玩家失误。

## Proposed design and trade-offs

### A. 对手移动：追球、回位、调动破绽分开

新增参数，取代共用的 `aiSpeed`、`aiRecovery`：

| 参数 | 初始值 | 含义 |
|---|---|---|
| `aiChaseSpeed` | 3.8 | 追球横向速度（经过 `aiDelay` 0.25 秒后开始） |
| `aiRecoverSpeed` | 1.3 | 回中路的横向速度 |
| `aiWideX` | 1.8 | 击球点横向位置超过它，视为「被调到边路」 |
| `aiStagger` | 0.3 | 从边路击球后，原地停顿这么久才开始回位 |

调动的意图：对手从边路回球后，要先停顿，再慢慢回位；这时玩家把下一球打向另一侧，它就要从边路横跨全场去追。能否追上由真实的移动距离和时间决定，不硬编码漏球。

否决「直接把速度调回 4.2」：回位也会跟着变快，玩家的落点调动就失去意义，回合又会变成无休止的互相接住。

### B. 重炮：先检查时间，施压但留机会

1. **出招前检查时间**：决定打重炮时，从预测轨迹算出对手到击球点还剩多少时间（`s.flight.contact` 的时刻减去当前球龄），并检查对手能否在这段时间内追到击球点。剩余时间少于 `tell + tellMargin`（初始 0.5 + 0.1 秒），或者追不到，就改打普通球，并记录事件 `heavySkipped`。
2. **施压**：重炮打向远离玩家的角落，保持现状。玩家用普通方式碰到重炮会回成软球，这就是「保命」；软球会引来下一记重炮，压力持续。
3. **留机会**：精准反制要更容易取得主动。初始把 `counterDelay` 从 0.15 提高到 0.25，反制回球打深（保持 9.2）；如果实验显示反制收益仍不明显，可以在 A 节允许的范围内继续调大，也可以让对手在被反制后回出浅球。实际取值写进实施记录。
4. **重炮连续施压**（Amendments 第 2 轮新增）：同一分里，从上一次反制成功（或本分开始）算起，对手打出的第 k 记重炮：
   - 速度乘以 `1+heavyRamp×(k−1)`，最多乘到 `heavyRampCap`；
   - 落点横向位置向边线推进 `heavyWiden×(k−1)`，最远到 x=±3.4。
   - 初始值 `heavyRamp=0.12`、`heavyRampCap=1.36`、`heavyWiden=0.2`，调参范围 `heavyRamp` 0.08–0.2、`heavyRampCap` 1.2–1.5。
   - 玩家用普通方式碰到重炮仍然回成合法的软球，规则不变；只是对手越打越狠，普通接法终会接不住。
   - 玩家反制成功，或者这一分结束，k 归零。
   - 前兆不少于 0.5 秒的要求不变，出招前仍要检查剩余时间。
5. **重炮触发间隔可调**（Amendments 第 3 轮新增）：原来「对手连续第 4 次击球必打重炮」中的 4 改为参数 `heavyEvery`，初始 4，调参范围 3–5（整数）。软球、浅球两种触发条件不变，前兆和时间检查的要求不变。

### F. 出球方向按球场位置（Amendments 第 2 轮新增）

玩家击球的落点横向位置改为由出手时机直接决定，与击球点的横向位置无关：
- 时机 `t` 越早，落点越靠对手场地左侧；越晚越靠右；`t=0` 落在中路附近。落点横向位置随 `t` 单调变化，`|t|` 较小时覆盖 ±2.9 以内的区域。
- 极早或极晚（`|t|≥0.7`）走借墙路线：先撞同侧侧墙，再落在同侧边路。
- 软球、重炮、反制的纵深和速度规则不变，只是横向目标改用这套映射。
- 实施方可以在满足以上性质的前提下确定具体公式，并写进实施记录。
- 否决「保持 落点 = 击球点 − t×5.8」：同一个时机会因为击球位置不同而落到不同地方，玩家难以预判，而且「永远早打」成了最强打法（原 S 打法胜率 99.6%）。

### G. 反制自动打空当，并有保底速度（Amendments 第 3 轮新增）

反制成功（面对重炮，`|t|≤counterWindow`）时：
- **方向不再由时机决定**：回球自动打向离对手当前横向位置最远的一侧，目标横向位置为 `x = −sign(对手x) × counterAimX`；对手正好在 x=0 时，取玩家所在的另一侧。`counterAimX` 初始 2.9，调参范围 2.4–3.2。
- **保底速度**：回球速度为 `min(counterMax, max(counterMinSpeed, 来球速度 × counterScale))`。`counterMinSpeed` 初始 11，调参范围 10–12.5；`counterScale`（1.1）和 `counterMax`（12.5）不变。
- 纵深仍为 `counterDepth`，对手的额外反应延迟仍为 `counterDelay`，反制成功仍会让重炮连续施压归零。
- 普通球、重炮、软球的方向仍按 F 节由时机决定，只有反制例外。

否决「只加保底速度、方向仍由时机决定」：反制要求时机居中，按 F 节就会打向中路，在结构上取不得主动。第 2 轮数据也印证了这一点：主动反制的胜率比只用普通回击低 13 个百分点。

### H. 回合越长球越快（Amendments 第 3 轮新增）

同一分里，按本分已经发生的击球次数 `n`（双方合计，含发球后的每一拍），双方的普通球、重炮基础速度、软球的速度都乘以 `min(rallyCap, 1 + rallyStep × n)`：
- 普通球和软球用这个倍数缩短飞行时间，落点不变；重炮先乘这个倍数，再乘 B 节第 4 条的施压倍数，总倍数仍受 `heavyRampCap` 和 `counterMax` 等既有上限约束（实施方写明组合方式）。
- 反制按 G 节的公式计算，不再额外叠加这个倍数。
- 每分重新开始时恢复为 1。
- `rallyStep` 初始 0.04，调参范围 0.02–0.06；`rallyCap` 初始 1.5，调参范围 1.3–1.6。
- 用意与原版守门游戏「回合越长球速越快（×1.05，最高 1.6）」一致：长拉锯自然会有人接不住，不靠超时判负。

### C. 两种打法对比实验（`scripts/rally-balance.mjs`）

新增一个不开浏览器、结果可复现的模拟脚本，直接调用 `rally-core.mjs`。

**模拟玩家**：几种打法共用同一套「人」的能力：
- 移动速度与真人相同（`playerSpeed`），看到来球后有 0.18 秒反应时间才开始移动，移到预测击球点；
- 出手时机：对每颗来球先选一个目标时机 `t目标`（由打法决定），再叠加正态噪声 `ε~N(0,σ)`，在击球预览的时机第一次达到 `t目标+ε` 时挥拍；
- 三档水平：`σ` 取 0.12（熟练）、0.25（一般）、0.40（新手）。

**打法**（`t目标` 的选法，打向哪一侧由正负号决定）：

| 打法 | 普通来球 | 重炮来球 |
|---|---|---|
| 普通回击（N） | ±0.5，打向对手的空当一侧 | ±0.5，不主动反制 |
| 主动反制（C） | 同 N | 0，瞄准反制窗口 |
| 固定一侧（S） | 永远选择让落点在对手场地同一侧（真实场地位置，固定为左半边）的时机，不论对手站在哪里（Amendments 第 2 轮修正） | 同 C |

C 与 S 的区别只在于是否换边调动，用来衡量「调动能得分」。

**规模与输出**：每种打法、每档水平各打 200 局，种子固定。结果写入 `artifacts/rally/balance.json`，并在终端打印表格。每组的统计项：
- 玩家每分胜率；
- 每分击球数的中位数和平均数；
- 每分的对手重炮次数，以及 `heavySkipped` 的次数；
- 面对重炮时，按「普通回击」「反制成功」「挥空」分组后的本分胜率；
- 失分原因分布（下网、出界、首次落在己方半场、二次弹地、挥空）；
- 对手最后一拍丢分时，需要追的横向距离。

**实验目标**（本设计提出的初始假设，用户批准设计即确认；只针对机器人数据，不代表真人结论）：

| 用户目标 | 判定方法（σ=0.25，一般水平） |
|---|---|
| 普通球能来回 | 另跑一组「关闭重炮」的打法 N（对手永远不打重炮），每分击球数中位数 ≥ 6（Amendments 第 2 轮修正） |
| 强攻会施压 | 打法 N 按每一颗来球统计：接重炮时没能回球的比例，比接普通球时没能回球的比例高至少 15 个百分点（Amendments 第 2 轮修正） |
| 读招能获益 | 打法 C 的每分胜率比打法 N 高至少 10 个百分点；反制成功的那一分，玩家胜率 ≥ 70% |
| 调动能得分 | 打法 C 的每分胜率比打法 S 高至少 10 个百分点 |
| 不是一边倒 | σ=0.12 时打法 C 每分胜率 ≤ 85%；σ=0.40 时打法 N 每分胜率 ≥ 20% |

**有效性**（Amendments 第 2 轮新增）：九组以及「关闭重炮」组的每一局都必须在 500 秒的模拟上限内打完；有未完成的局，整次实验视为不达标。

调参只能动 A、B 两节列出的参数（含 B 节第 4 条的施压参数、第 5 条的 `heavyEvery`）、F 节映射公式的系数、G 节的 `counterAimX` 与 `counterMinSpeed`、H 节的 `rallyStep` 与 `rallyCap`（均限于各自写明的范围），以及对手普通球的落点选择（比如偶尔打回中路），不能改其他规则。调到全部目标达成后，把最终参数和完整结果表写进实施记录。如果调不到，就如实记录最接近的一组，状态停在 implementing，并说明卡在哪个目标上。

## Risks and approval boundaries

- **调不到全部目标**：如实记录，不得为了达标去改规则，也不得硬编码让对手漏球或得分。状态停在 implementing，并在 Deviations 写明卡在哪条。
- **改动实验目标需要询问**：C 节的目标数字和三档水平 σ 是用户批准的假设，实施方不得自行放宽。第 2 轮只修正了三条指标的量法，数字没有变。
- **规则变更范围**：第 2 轮批准了 B 节第 4 条和 F 节，第 3 轮批准了 G 节、H 节和 B 节第 5 条，此外不得再引入其他机制。如果加了这些仍然达不到目标，如实记录并停下来询问。
- **并发**：`dist/art.mjs`、`dist/scene3d.mjs`、`dist/crowd.mjs`、`README.md` 有其他代理的未提交改动，不得写入，也不得放进提交。
- **不得**合并到 main，不得发布或部署。
- 机器人结果只用来决定参数能不能拿去试玩，不能写成「玩家会觉得好玩」。

### 第 2 轮（2026-10-23，设计复议）

- **背景**：实施方完成任务 0–3、5、6，任务 4（调参达标）失败。在设计允许的参数内试了 46 组参数，并用 200 局做了全量复核，最终 C 节五行目标中只有「读招能获益」达标，并且多组出现 500 秒仍未打完的局（见 02-implementation.md「C节五行目标」与 Remaining risks）。设计方复议后认为：
  1. 「普通球能来回」「强攻会施压」按「本分是否出现过重炮」分组，而打得久的分几乎必然出现重炮，所以无重炮组基本都是开局就挥空的短分（无重炮分玩家胜率 0%、中位 4 拍），指标量的不是本意。这是设计缺陷。
  2. 「固定一侧」定义成固定时机 +0.5，而落点相对击球点计算，再加上侧墙，并不固定在一侧；S 胜率 99.6%，反而暴露「永远早打」是一招鲜。这是设计缺陷。
  3. 不反制时「软球 → 重炮 → 软球」可以无限循环（最长一分 205 拍），在允许的参数范围内无法打破。
- **向用户提出的问题与回答（原话）**：
  - 「实验里量不准的三条指标，是否改用下面的量法（目标数字保持不变）？」→「按推荐量法修正（推荐）」
  - 「是否加入「重炮连续施压」机制，让不反制的回合能结束？」→「加入施压升级（推荐）」
  - 「出球方向是否改成「早打落到对手场地左半、晚打落到右半」（按球场位置）？」→「改为按球场位置（推荐）」

  - C 节：「普通球能来回」改为单独跑一组关闭重炮的 N；「强攻会施压」改为按每颗来球统计回球失败率；S 改为固定打向对手场地左半边；新增「所有局必须打完」的有效性要求。目标数字和 σ 不变。

### 第 3 轮（2026-10-23，设计复议）

- **背景**：第 2 轮实施了 B4 与 F，并修正了三条量法。C 节五行中「普通球能来回」「强攻会施压」「调动能得分」三行数值达标；「读招能获益」失败（一般水平 C 比 N 低 13.15 个百分点，反制成功的那一分胜率为 84.29%），「不是一边倒」失败（熟练 C 为 93.63%），有效性失败（2000 局中有 3 局 500 秒未完，其中 1 局是关闭重炮的对照组）。见 02-implementation.md 第 2 轮「五行目标与有效性」与 Remaining risks。设计方复议认为：
  1. 反制要求时机居中，F 节又让时机居中落到中路，所以反制回球在结构上打向中路，取不得主动；反制速度只是来球 × 1.1，早破招（第 1 记重炮较慢）反而收益最小，与设计意图相反。
  2. 没有重炮时，双方普通球可以无限来回，缺少回合终结机制。
  3. 反制变强后，熟练玩家可能更加碾压对手，需要一个能提高对手威胁的调节项。
