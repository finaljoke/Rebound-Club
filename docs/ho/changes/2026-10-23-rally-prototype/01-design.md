# 墙网球对打小样：隔网对打、强攻型重炮前兆与精准反制

## Background and goal

现有游戏是「守门回球」：对手是一名只会拦截的 AI 门将，玩家把球打进它身后的球门。用户希望向《网球王子》式的「读招、破招、反击」体验发展：对手主动出球、出招有前兆、玩家识别后用操作破解并获得进攻机会。是否整体转向尚未决定，因此先做一个**可以被推翻的对打小样**，与现有游戏并存，用来验证：

- 普通回合是否让人想继续接下一球；
- 玩家能否读懂落点和对手动作；
- 一次完整的「出招—破解」链路是否有成就感：对手明显引拍蓄力 → 打出重炮 → 玩家识别前兆 → 看准时机反制 → 获得进攻机会。

对外定位暂称「潮玩超能网球」，侧墙作为玩法特色保留。

## Confirmed decisions

来源：用户 2026-10-23 的两轮讨论（第一轮评估反馈，第二轮用户提出四处调整后确认）。

1. 先做小样，不替换现有游戏；现有守门版本留在 main，可照常发布。
2. 保留侧墙，做成「隔网对打 + 侧墙参与反弹」的街机规则。
3. 小样范围（用户原表）：一张隔网球场、保留侧墙；玩家球拍、左右移动、辅助前后站位；一名强攻型对手，有清楚的重炮前兆；玩家球技为普通回击 + 精准反制；自动轮流发球，抢 5 分；重点验证「接得住、看得懂、反制成功有成就感」。
4. **完整的出招—破解链路必须在同一个验证版本里**（修正了第一轮评估中「反制放到小样通过之后」的矛盾）。弧线球随后再加；爆发特写在验证阶段关闭。
5. **「弹跳最高点＝完美」只作为实验方案**：小样提供清楚、略宽容的击球高度窗口，保留「时机选方向」；「最高点奖励」与「精准接触奖励」两种完美规则都实现、可切换比较，不提前锁死。
6. **侧墙与合法顺序（用户首版规则）**：
   - 侧墙始终有效，碰墙不计弹地次数；
   - 每次回击后，球必须越网，且第一次落地在对方半场；
   - 在对方半场第二次落地，对方失分；
   - 下网、底线出界、首次落在己方半场，击球方失分；
   - 普通回击优先生成合法球路，先让玩家把注意力放在左右落点和破解上。
7. **数据指标只作观察依据，不作通过标准**。记录以明确事实为主：下网、出界、二次弹地、挥空、反制成功；「对手制胜 / 我方失误」这类归因不写入记录。
8. 不做网前截击（第一轮建议，用户未反对）：玩家只在球第一次落地之后击球。
9. 不分局盘，无发球失误。

## Current state with evidence

以下均为阅读代码得到的事实（main = `69abec5`，工作区另有他人未提交的观众改动）。

- **球没有真实高度。** `dist/core.mjs` 的球状态只有 `x,z,vx,vz`（`createGame` 第 65 行）；`ballHeight(s)` 只按纵深进度画抛物线，注释写明「Drawn height only (no rule reads it)」。过网、弹地、击球高度在现有规则里都不存在。
- **运动推进是平面的。** `advanceBall(b,dt)`（core.mjs 第 34 行起）处理平面位移、旋转曲率和侧墙镜面反射（`SIDE=3.82`，反射时横向速度取反，无能量损失）。
- **球员只左右移动。** `s.player.x` 以 6.2/秒移动并限制在 ±3.45（core.mjs `tick`）；纵深固定 `PLAYER_Z=1.6`。
- **时机决定方向。** 挥击由 `windup/active/recovery/whiff` 组成（`WEAPONS.racket`：0.05/0.13/0.2/0.5）；接触时刻在击球带中的位置 `t∈[-1,1]` 决定出球角 `angle=-t*MAX_AIM`（`MAX_AIM=.45`，core.mjs 第 121 行）；`|t|≤PERFECT_BAND(.3)` 为完美重炮；早挥未进入有效带为软球。
- **对手只会拦。** 门将在球过 `KEEPER_Z` 时判一次扑救（`farEnd`），扑回的角度由固定公式给出，没有意图和前兆。
- **输入。** `dist/input.mjs` 的 `createInput()` 提供 `axis()`（-1/0/1）、`down(id,dir)`、`up(id)`、`key(key,down)`、`pressed(dir)`、`reset()`；方向按钮与键盘都已接好（`dist/game.js`）。

## Proposed design and trade-offs

### A. 形态：独立页面、独立模块，与现有游戏并存

新增页面 `dist/rally.html`（本地访问 `http://localhost:4173/rally.html`），由 `dist/rally.js` 接线，规则在 `dist/rally-core.mjs`，画面在 `dist/rally-scene.mjs`。只**导入**现有的 `input.mjs`、`art.mjs` 和 `vendor/` 中的 Three.js，不修改它们。

- 否决「在现有 `core.mjs` 上加模式开关」：会同时改动 13 个依赖守门规则的测试文件和正在发布的版本，违背「可被推翻」。
- 否决「改写 `scene3d.mjs` 复用场景」：该文件正由另一位代理修改；对打场景的球网、镜头和对手动作也与守门场景差异很大。
- 发布脚本排除 `rally` 开头的文件，小样不进入发布包。

### B. 场地与坐标

物理坐标：`x` 左右，`y` 高度（新增，参与规则），`z` 纵深。

| 名称 | 初始值 | 说明 |
|---|---|---|
| 侧墙 | x = ±3.82 | 与现有 `SIDE` 一致，始终有效 |
| 玩家底线 / 球网 / 对手底线 | z = 0 / 5 / 10 | 玩家半场 0–5，对手半场 5–10 |
| 球网高度 | 0.62 | 全宽一致 |
| 重力 | 6.0 | 街机手感，非真实值 |
| 落地反弹 | 竖直速度 ×0.72，水平速度 ×0.9 | |
| 撞墙 | 横向速度取反，系数 1.0 | 保证「借墙」路线可预测 |

所有数值集中在 `RALLY` 配置对象里，实现者可在验收范围内调整。

### C. 判定顺序（用户首版规则的实现方式）

每一拍都记录「击球方」和「本拍落地次数」。

1. 回击发生：击球方 = 打出这一拍的人；落地次数清零。
2. 球心越过 z=5 平面时，若高度 < 球网高度 → **下网**，击球方失分。
3. 第一次落地：
   - 落在击球方自己的半场（未越网）→ **首次落在己方半场**，击球方失分；
   - 越过对方底线（玩家击球时 z>10，对手击球时 z<0）→ **底线出界**，击球方失分；
   - 否则为合法落地。
4. 合法落地后第二次落地（无论在哪里）→ **二次弹地**，接球方失分。
5. 碰侧墙只改变方向，不计落地次数，也不改变击球方。
6. 接球方挥空，且球随后二次落地，记为 **挥空** 失分。

失分原因只记录以上事实：`net`、`out`、`own-half`、`double-bounce`、`whiff`。

### D. 合法球路生成（普通回击优先合法）

击球时不直接给速度，而是先选**落点**，再解出能到达该落点并越网的初速度：

- 落点横向位置由时机决定方向（与现有一致：早打往左、晚打往右），映射到对方半场内的横向目标；
- 落点纵深按出球类型确定，比如普通球打深、软球打浅；
- 用「飞行时间」反解初速度，再检查越网时的高度；高度不够就延长飞行时间重解；
- 目标横向位置超出侧墙时，按镜像位置求解，球撞墙后正好落回目标点，这就是「借墙」。

**[设计判断]** 这样玩家打出的普通球永远合法，失分只来自接不住，玩家的注意力会集中在落点和破解上。下网、出界这些规则仍然完整实现：对手的强攻失误会用到，后续加入高风险球招时也会用到。

### E. 玩家击球

- **移动**：左右由方向按钮控制（复用 `input.mjs`）；前后由系统自动走到预测的击球深度，有移动速度上限。
- **击球窗口**：只在球第一次落地之后，球进入玩家前方的击球区，并且高度在 0.2–1.7 之间（略宽容）时有效。
- **时机定方向**：挥击接触时刻在窗口中的位置 `t∈[-1,1]`，决定左右方向，与现有手感一致。
- **两种「完美」规则，可切换比较**（用户确认的实验）：
  - **精准接触**（默认）：`|t|≤0.3` 打出重炮；
  - **最高点**：接触时刻在弹跳最高点前后 0.08 秒内打出重炮，方向仍由 `t` 决定。
  - 用网址参数 `?power=apex` 切换到「最高点」，记录里写明当前用的是哪一种。
- **软球**：在窗口边缘接触（`|t|>0.85`）打出慢速浅球，仍然合法，但会给对手进攻机会。
- **挥空**：整个挥击期间都没有碰到球，进入 0.5 秒收招时间。

### F. 强攻型对手

- **移动**：反应延迟 0.25 秒，横向速度 4.2，自动走到击球深度。**破绽**是击球后回中路很慢，只有正常速度的 45%。
- **普通回球**：打向远离玩家当前位置的一侧（空当），落点有确定性的小偏差。
- **重炮触发**：满足以下任一条件，就会在来球越网后决定打重炮：
  - 玩家打出软球；
  - 玩家的球落在对手半场靠前的位置（z<7.2）；
  - 一回合里对手连续第 4 次击球。
- **前兆**：决定打重炮后立即开始引拍蓄力，**距离击球至少 0.5 秒**，同时有三种提示：
  - 动作：球拍高举后拉，身体侧转；
  - 脚下出现橙色蓄力环，球拍发光；
  - 音效：上扬的蓄力声。
- **重炮**：速度约为普通球的 1.6 倍，弧线低平，打向远离玩家的角落，正常情况下合法。
- **强攻失误**（破绽，也用来让「出界」规则真实出现）：对手被逼到底线后（击球点 z>10.3）打出的重炮会**出界**。玩家把球打深，就能诱发这个失误。

### G. 精准反制

- **不新增按钮**：用同一个挥击键。面对对手的重炮时，接触时刻满足 `|t|≤0.18`（比普通完美的 0.3 更窄）即为**反制**。
- **效果**：借力回球，速度为来球的 1.1 倍（有上限），弧线低平、打深，方向仍由时机决定；对手的下一次反应额外延迟 0.15 秒（被打乱节奏）。这就是「获得进攻机会」：对手回位又慢，打向空当很可能直接得分。
- **没打准**：碰到了重炮但不在反制窗口内，回成软球，对手大概率再打一记重炮；挥空就失分。
- **反馈**：「反制！」飘字、球拍闪光、专属音效，并记录事件 `counter`。
- **否决「专用反制按钮或架势」**：读招的价值确实更高，但会多一个按钮，还要为假动作设计惩罚。小样阶段对手没有假动作，留待以后。

### H. 比赛流程与记录

- **发球**：自动轮流，玩家先发。发球是由系统生成的合法球，没有发球失误。
- **每分结束**：停 1.2 秒，在画面上显示失分原因（下网、出界、首次落在己方半场、二次弹地、挥空），然后下一分。
- **比赛**：先得 5 分获胜。结算页显示比分和逐分记录，按钮有「再来一局」和「复制记录」。
- **复制记录**：复制为 JSON，每分包括：分数序号、发球方、本分击球数、失分原因、失分方、对手重炮次数、玩家面对重炮的次数、反制成功次数、当前的完美规则。

### I. 画面与可读性

- **场景**：在 `rally-scene.mjs` 中搭建隔网场地。
  - 草皮复用 `makeSurfaceTexture`，球网用 `netGeometry`，球员复用 `buildAthlete`；
  - 球拍模型参照 `scene3d.mjs` 的写法，在本文件里另写一个；
  - 静态物件用 `mergeRigidParts` 合并；
  - 不加观众。
- **镜头**：在玩家身后。用 `scene3d.mjs` 的约束搜索方法重新定构图，要求两条底线的四个角、球网两端、对手头顶和玩家头顶都在画面内，竖屏和横屏都要满足。
- **读球提示**（和现有游戏一样，提示与真实飞行用同一套计算）：
  - 球的地面影子；
  - 来球的**第一次落地预测圈**；
  - 玩家的击球区，进入窗口时变亮。
- **对手前兆**：见第 F 节，引拍蓄力期间三种提示都要出现。
- **减少动态效果**：不震屏，蓄力环不脉动，其余照常。
- **暂停**：画面和规则都静止，做法同现有游戏的「场景时钟暂停即停」。

### J. 验证方式（用户确认：数据只作观察依据）

小样完成后找真人试玩，观察以下几点：
1. 玩家看到对手蓄力后，是否真的改变了接法，比如提前移动、更专注时机；
2. 失分后，玩家能否说出自己哪里判断错了；
3. 同一招被破解后，玩家是否愿意换一种打法；
4. 没有任何解锁奖励时，玩家是否主动再打一局。

「复制记录」提供客观事实作为辅助，「平均 4–8 拍」只作为初始参考，不作为通过标准。小样阶段同时比较「精准接触」和「最高点」两种完美规则，看哪种更顺手。

## Risks and approval boundaries

- **并发**：`dist/art.mjs`、`dist/scene3d.mjs`、`dist/crowd.mjs` 正由另一位代理修改，小样不得修改这三个文件。如果 `art.mjs` 的导出名称发生变化，小样跟着调整导入；如果小样需要它们新增导出，先停下来询问。
- **规则变更需要询问**：C 节的合法顺序和失分归属、「普通回击优先生成合法球路」、不做截击、抢 5 分，都是用户确认的决定。数值（重力、速度、窗口宽度、触发阈值、前兆时长不少于 0.5 秒）可以在验收范围内调整，并写进实施记录。
- **不得**改动现有守门游戏的页面、规则、存档、大厅入口和发布内容；小样不得加进大厅。
- **不得**发布或部署小样，也不得生成包含小样的发布包。
- **手感风险**：重力、反弹和窗口宽度第一次取值不一定好打，这是预期内的，靠试玩调整。如果「读球机器人」都打不完一局，说明数值有问题，要先调数值，不能放宽判定规则。
- **工作量估计**（设计判断，误差可能有一倍）：规则 2–3 天、对手 AI 约 2 天、画面约 2 天、页面与检测 1–2 天。
