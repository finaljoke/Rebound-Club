# 反弹守卫 · 第一轮改造：AI 守门员对决 + 核心手感

日期：2026-10-22
范围：只做「P0」——核心玩法和手感。界面全屏化、关卡机制、装备差异化、留存系统都不在本轮。

## 1. 为什么改

现版本（Codex 版）的问题在玩法，不在画面：

- **连按必中。** 拳套挥击周期 0.425s、判定 0.23s，两次判定之间空 0.195s；球穿过击球区约 0.3s，比空隙长。站在球的连线上一直按空格就一定打中。球拍、剑和最高关速度下同样成立。
- **移动没压力。** 人物横穿半场约 1.1s，来球要 2s 以上，横向偏移又小，永远来得及。
- **「漂亮回击」判定的是自己挥击节奏的中段，与球的位置无关**，玩家感知不到什么叫打得好。
- **回球没有目标。** 远端是一面会晃的墙，打到哪都一样。
- **难度平。** 6 关只是球速 4.3→5.3，回合内球速也不变。
- **反馈弱。** 球固定高度贴地滑行，无落点；击中无顿帧、无震屏；音效是单个正弦波。

结果：挂机几秒就输，对齐加连按又基本不会输，两头都没有张力。

## 2. 这一轮要做成什么

**一句话：一颗球的 1v1 攻守对决。** 你守近端球门，AI 守门员守远端球门。你把球打回去要想办法打进对方门；AI 扑住了，球会被它挡回来，轮到你再防。

目标体验：

1. 「打中」需要看准时机，连按会被惩罚。
2. 「打到哪」由时机决定，玩家有瞄准的意图。
3. 一个回合越打越快，打进一球是明确的高潮。
4. 每一次击中、扑救、进球、丢球都有足够强的手感反馈。

### 非目标（本轮不做）

- 手机全屏竖屏布局、营销文案的收纳（P1）。
- 按机制区分的关卡（弧线球、假球、双球等）、三星评价（P1）。
- 装备玩法差异化（P1）。三种装备本轮保留，只按新判定规则调参数。
- 无尽模式、排行榜、每日挑战、皮肤（P2）。
- 微信小游戏接入。

### 反目标（做出来但出现这些就算失败）

- 连按仍然能稳定得分或稳定防守。
- 玩家看不懂球为什么飞向那个方向。
- AI 守门员表现得「全知」（每球必扑）或「呆滞」（站着不动）。
- 帧率在中档手机上明显下降。

## 3. 规则（已定）

坐标沿用现有 `core.mjs`：x 为横向（左负右正），z 为纵深，玩家在近端 z≈1.6，近端球门线 z=0，远端在 z≈9.8。

### 3.1 场地

- 两侧墙不变，球碰侧墙镜面反弹。
- 远端是一面墙，**中间开一个球门口**（门宽随关卡变化，见 3.6）。球打到门口以外的墙面会正常反弹回来，同时加入现在回弹板那样的小幅角度扰动。
- 远端门口前站着 AI 守门员，只沿 x 方向左右移动。
- 原来的「会晃的回弹板」去掉，由墙面 + 门 + 守门员替代。

### 3.2 击球判定（以球的位置为准）

- 每件装备有一个**甜点**：玩家前方 `reach × 0.5` 的位置。
- 挥击有出手（windup）→ 判定（active）→ 收招（recovery）三段。判定窗口内，球进入击球区就算击中。**击中质量由击中瞬间球与甜点的纵深距离决定**，不再看挥击进行到第几成：
  - 离甜点足够近 → **完美**（重炮，见 3.4）。
  - 其余 → 普通击中。
- **仓促软球**：如果判定窗口打开时球还没进入击球区，之后球自己「撞上」正在挥动的装备，算作仓促软球：方向固定为直线（不受时机影响）、出球速度 ×0.8、不会判完美。只有「窗口打开那一刻球已在击球区内」的击球才是正常击球，才有方向和完美判定。这样「提前挥等球撞上来」只能打出软直球，守门员容易扑住。
- **挥空惩罚**：判定窗口结束仍未击中，收招时间额外加长（whiff recovery）。参数必须满足：**挥空后到下一次判定窗口开始的间隔，大于本关基础球速（回合最慢的速度）下球穿过击球区的时间**。这样连按必然出现漏洞。验收：在第 1 关基础球速下，站在球路上、每帧都按挥击，三种装备都至少漏掉 30% 的来球。这条要有测试保证（见第 5 节）。
- 人物身体依然不会自动挡球（保留现有规则）。

### 3.3 时机决定方向

- 击中时，根据球与甜点的纵深偏差计算出球方向：
  - **早挥**（球还在甜点前方、离玩家较远时就打中）→ 球往**左**飞。
  - **晚挥**（球已过甜点、离玩家较近时才打中）→ 球往**右**飞。
  - 正中甜点 → 直线。
- 偏差到角度是连续线性映射，最大角度大约 ±0.6 rad（具体值由实现者调）。
- 玩家与球的横向偏差**不再**影响方向，只决定能不能打到。规则只留一条，便于理解。
- 完美球离甜点近，所以接近直线。重炮靠**走位**瞄准：站在边路打直线重炮，就是打门角。时机控制角度，走位控制落点。
- 帮助说明和首次开局提示要写清「早打往左、晚打往右、正中直线」。

### 3.4 回合内加压和重炮

- 一个回合从发球到一方进球为止。
- 玩家每击中一次，回合球速 ×1.05，上限为本关基础速度的 1.6 倍。进球或丢球后重置。
- **完美击球 = 重炮**：这一击的出球速度额外 ×1.35，只对这一程生效。守门员挡回来后恢复为回合球速。重炮要有专属的视觉和声音。

### 3.5 AI 守门员

守门员必须是**确定性**的，不用随机数，便于测试和调参。它的行为：

- 球朝远端飞行时，守门员预测球到达门线时的 x，并朝该点移动。
- 三个调节量：
  - **反应延迟**：玩家击球后过一段时间才开始移动。
  - **最大横移速度**。
  - **预判误差**：预测点加一个确定性的偏移（例如由本回合击球次数推出），让它有时会扑错方向。
- 守门员不预测侧墙反弹之后的路线，只按当前直线预判。这是我的设计选择：打侧墙反弹进门成为一种有效的进阶打法。
- 球到达门线时，若守门员的身体（有一定宽度）覆盖球的 x → **扑救成功**，球被挡回玩家方向。出球角度由球打在守门员身上的位置决定，速度为当前回合球速。
- 若没覆盖且球在门口内 → **玩家进球**。
- 球打到门口以外的墙面 → 正常反弹，守门员不参与。
- 球朝玩家飞行时（以及发球、进球后），守门员以较慢速度（约最大横移速度的 35%）往门中间回位，不会瞬间归中。所以连续进攻时，它的位置会被你调动。
- 守门员不射门，只扑救。它挡回来的球就是玩家要防的「进攻」。
- 重炮不需要特殊规则：球速更快，守门员反应和横移就自然更难跟上。

### 3.6 胜负和关卡

- **通关**：先进 N 球。
- **失败**：丢 3 球（沿用现有 3 次机会）。
- 丢球后进度保留，与现规则一致。
- 6 关保留，本轮只用参数区分难度，下表为起始值，实现者可以调：

| 关 | 名称 | 进球目标 | 基础球速 | 守门员反应 | 守门员速度 | 门宽 |
|---|---|---|---|---|---|---|
| 1 | 初次交锋 | 3 | 4.3 | 慢 | 慢 | 宽 |
| 2 | 左右开弓 | 3 | 4.6 | ↓ | ↑ | ↓ |
| 3 | 预判时刻 | 4 | 4.9 | | | |
| 4 | 节奏大师 | 4 | 5.2 | | | |
| 5 | 全场奔袭 | 5 | 5.5 | | | |
| 6 | 守门王牌 | 5 | 5.8 | 快 | 快 | 窄 |

调参的验收标准：第 1 关，新手正中直线的普通击球大多会被扑住，打边角或重炮通常能进；第 6 关需要重炮或侧墙反弹才比较容易进。

### 3.7 计分

- 进球 1000 分；重炮进球再加 500。
- 每次成功回击 100，完美 +50。
- 连击沿用现有逻辑：漏球清零，进球不清零。

## 4. 手感和画面（已定的部分）

- **球的弧线**：模拟仍然是二维 (x,z)，高度只是视觉效果。每一程（一方出球到另一端）画一条抛物线高度，地面有影子和落点圈，让玩家看得出纵深。
- **顿帧**：完美击球时模拟暂停约 60–80ms，进球时约 120ms。reduced-motion 模式下关闭。
- **镜头微震**：重炮、进球、丢球时触发，幅度小。reduced-motion 下关闭。
- **击球音效**：用 WebAudio 合成，不引入音频文件：低频「咚」+ 短促噪声「啪」叠在一起。普通、完美、扑救、进球、丢球各有可区分的声音。进球要有明显的庆祝音。
- **守门员模型**：风格与现有玩家人物一致（圆润、体块化），换一种球衣颜色；扑救时有侧扑动作。
- **远端球门**：与近端球门同样的结构（立柱、横梁、网），门宽随关卡变化。
- **镜头**：要能同时看清两个球门和球的高度。现在的镜头很陡，可以压低一些。具体位置由实现者调整，用截图确认。
- **2D 兼容画面**保留，并同步画出守门员、远端门和门口。只要能玩，不追求精细。

## 5. 测试要求

在现有 `node --test` 体系内补充或改写 `tests/core.test.mjs`：

- 对每件装备、第 1 关基础球速：站在球的连线上、每帧都按挥击，至少漏掉 30% 的来球（用不同到达相位模拟统计）。
- 早挥往左、晚挥往右、正中直线。
- 完美判定只取决于球与甜点的距离。
- 回合球速每击 ×1.05，有上限，回合结束重置；重炮只影响一程。
- 守门员：慢速正中球被扑住；快速角球进门；打到门口外的墙面正常反弹；同样的输入得到同样的结果（确定性）。
- 进 N 球通关、丢 3 球失败，计分符合 3.7。
- 现有关于暂停、输入、存储降级的测试继续通过。
- `npm test` 和 `node --check dist/game.js` 通过。
- 用浏览器实际打几局，桌面和手机两种宽度都截图确认。

## 8. 设计中由我（Claude）做的决定

用户已经确认整体方向（P0、时机决定方向、回合加压、重炮、加 AI 守门员）。以下细节是我定的，用户可以推翻：

- 守门员不预判侧墙反弹（打侧墙反弹进门作为进阶打法）。
- 早挥往左、晚挥往右（不是反过来）。
- 玩家与球的横向偏差不影响出球方向。
- 远端是「墙 + 门口」，而不是整面都是门。
- 存档键升级，旧进度作废。
- 2D 兼容画面保留，但只做到能玩。
- 提前挥拍等球撞上来算「仓促软球」（直线、×0.8、无完美）。
- 挥空惩罚按基础球速校验，连按至少漏 30%。
- 重炮靠走位瞄准；守门员两次射门之间慢速回中。
